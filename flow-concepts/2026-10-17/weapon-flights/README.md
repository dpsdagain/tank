# Weapon flight concepts created in Google Flow

Generated in the user's existing Flow project on 17 October 2026 with Nano Banana 2.1, image mode, 16:9, one image for each of three prompts. Flow displayed 0 credits per generation. The user's original x2 output preference was restored afterward.

The three boards cover all 36 implemented weapons in the order of `weapons.js`:

1. `01-shells-wheels-weather.jpg`: Single Shot through Hail Storm (weapons 1–12).
2. `02-earth-homing-swarms.jpg`: Dirtball through Pin Cushion (weapons 13–24).
3. `03-energy-cosmic-jets.jpg`: Laser through Magic Wall (weapons 25–36).

These are the original downloaded JPEGs, preserved without retouching or removing the visible generated marks. Exact prompts are in `prompts.md`. `asset-metadata.json` records dimensions and formats. `flow-generation-view.jpg` records the generated results in the Flow UI.

## Visual review

All three boards have the twelve intended names in the intended order. The first board differentiates projectile count, metal sphere/disc/wheel shapes, fire liquid and ice. The second gives soil, mechanical tools, the worm, hive/bees and needle pod materially different bodies. The third distinguishes thin/wide beams, bombs, icy comet/fire meteor trails, living flame, lava, tank thrusters and stone.

The material shading, specular highlights and silhouettes are useful targets for a more painted version of the current Canvas flight artwork. The backgrounds/layout vary between boards, and some objects use a slight three-quarter presentation rather than a strict side-on view.

These are static concept boards, not ready animation atlases. They contain labels and scenery, and JPEG has no alpha transparency. Production integration would need separate clean projectile artwork, consistent side views/anchors and transparent exports; motion would still follow the existing game engine. The current playable game and its ZIP were not changed by this concept exploration.

Provider: Google Flow browser UI. Neither the built-in image generation tool nor the CLI fallback was used.
